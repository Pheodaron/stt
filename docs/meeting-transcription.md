# Расшифровка полной встречи

Реализация находится в ветке `diarization`. Живой bidi-метод продолжает принимать прежние Ogg/Opus-чанки. Новый метод принимает полную запись и возвращает один результат после окончания обработки.

## API

```proto
rpc TranscribeMeeting(stream MeetingRequest) returns (MeetingResponse);
```

Путь метода — `/Gigaam/TranscribeMeeting`. Последовательность сообщений:

1. `header.size_bytes`: полный размер исходного аудиофайла, больше нуля.
2. `chunk`: последовательные части файла, по умолчанию не более 1 MiB каждая; последний чанк может быть короче.
3. Клиент завершает отправку и ожидает один полный ответ. Сервер начинает декодирование только после EOF и проверки размера.

Чанки нового метода — диапазоны байтов файла, а не самостоятельные аудиофайлы. Они не декодируются по отдельности. Число сообщений и общая длительность записи не имеют прикладного лимита; действуют доступный диск и deadline клиента. Размер одного ответа ограничен protobuf — менее 2 GiB.

`MeetingResponse` содержит:

| Поле | Содержание |
|---|---|
| `duration_ms` | Длительность декодированного аудио |
| `speaker_ids` | Все обнаруженные голоса, номера 1..8 внутри этой записи |
| `diarization` | Интервалы `{start_ms, end_ms, speaker_id}`, включая пересечения |
| `segments` | Фрагменты `{start_ms, end_ms, speaker_ids, text, has_overlap, forced_split}` |

Время относится к исходной декодированной записи; паузы сохраняются. Время слов не возвращается. Если `speaker_ids` фрагмента содержит несколько голосов, авторство отдельных слов неизвестно. `has_overlap` сообщает об одновременной активности, не об успешном распознавании обеих реплик. Смешанный фрагмент распознаётся один раз.

Запись без обнаруженной речи возвращает длительность и пустые списки. Ошибка обработки возвращается gRPC status, а не частичной успешной расшифровкой.

## Обработка

```text
Чанки файла → временный исходный файл
    → один FFmpeg → PCM16 mono 16 kHz на диске
    → Nemotron через cgo → интервалы голосов
    → ASR-фрагменты до MAX_AUDIO_SECONDS, не более 25 секунд
    → общий GigaAM → один MeetingResponse
```

Nemotron загружается один раз при запуске gRPC-сервера. На запись создаётся отдельная сессия `v3-offline`; PCM подаётся в неё блоками по одной секунде без сброса speaker cache между блоками. Максимум — восемь разных голосов. Используются штатные пороги SDK, в том числе при свёртке истории длинных записей.

GigaAM вызывается напрямую, без текущего потокового `Session`, который удаляет паузы и повторно распознаёт окно. Короткое пересечение может объединяться с соседними участками для контекста; результат включает всех обнаруженных спикеров. Длинные реплики режутся по паузам Silero, при отсутствии паузы — по лимиту с `forced_split=true`. Padding добавляется только в свободную соседнюю тишину.

Source separation и суммаризация не входят в эту реализацию. Результат готов для передачи в суммаризатор.

## Параллельность и остановка

- Один файл загружается или обрабатывается одновременно на экземпляр сервиса. Второй RPC получает `ResourceExhausted` до чтения первого сообщения.
- Общий пул GigaAM обслуживает оба режима. Ожидающий живой вызов получает приоритет перед следующим фрагментом встречи. Открытый, но неактивный живой stream не блокирует встречу.
- Уже выполняющийся native Decode не прерывается. На CPU диаризация и FFmpeg также конкурируют с живой обработкой за ресурсы.
- Фоновых заданий и отдельных worker-горутины встречи нет. Вся обработка выполняется в текущем RPC.
- Отмена проверяется между блоками Nemotron и ASR-фрагментами. FFmpeg останавливается через context. Слот встречи и модель не освобождаются до возврата выполняющегося native-вызова.
- При SIGTERM новые встречи отклоняются, активная отменяется; gRPC ожидает handlers перед уничтожением моделей. Окончательный предел ожидания задаёт supervisor контейнера.
- Workspace закрыт файловой блокировкой; два процесса должны использовать разные каталоги. При запуске из него удаляются остатки `upload-*` предыдущего аварийного завершения.

## Контейнер и настройки

CPU — основной режим Nemotron в этой версии. В CUDA-образе GigaAM сохраняет CUDA, а Nemotron работает на CPU. Перенос Nemotron на GPU — отдельный следующий этап.

SDK закреплён на `66d50d91b75a406becd95fbaf39d2c9c13e95d7c`, checkpoint — на `a435e9867d79e789e90053f9b6d6834053af564a`. При сборке официальный converter создаёт GGUF с `--outtype f32`. В этом профиле один вес свёртки, `subpixel_upsample.weight`, сохраняется в F16: это требование CPU Conv1D в ggml. Остальные тензоры должны быть F32; другие F16, BF16 и квантованные веса валидатор отклоняет. Строгое исполнение всех операций в FP32 этот SDK не обеспечивает. GigaAM использует отдельный FP32 ONNX без этого исключения.

Валидатор проверяет архитектуру, восемь голосов и типы тензоров, записывает SHA-256, фактический состав типов и список F16-тензоров в manifest. При наличии штатного исключения `precision` равен `f32_with_f16_conv`, `conversion_outtype` — `f32`. Модель, SDK, его runtime-зависимости и лицензии входят в образ. Python и исходный checkpoint в runtime не копируются. Скачивания при запуске нет.

| Настройка | По умолчанию | Значение |
|---|---|---|
| `MEETING_CHUNK_BYTES` | `1048576` | Максимум payload одного сообщения, от 1 байта до 4 MiB |
| `MEETING_TEMP_DIR` | `/tmp/stt-meetings` | Выделенный writable-каталог исходника и PCM |
| `MAX_AUDIO_SECONDS` | `25` | Предел одного ASR-фрагмента, не всей встречи |
| `MODEL_WORKERS` | `1` | Общие экземпляры GigaAM |

Старый `REQUEST_TIMEOUT` ограничивает живую сессию на вызов, но не новую встречу. Клиент должен задать deadline на загрузку и всю обработку. Паузы в живом трафике и непрерывная нагрузка могут увеличить время встречи.

На два часа PCM16 нужно около 230,4 MB временного диска, дополнительно к исходному файлу до его удаления. RAM загрузки ограничена чанками и транспортными буферами; список результатов растёт с длительностью встречи. Для writable-каталога нужна дисковая ёмкость, не маленький RAM-backed tmpfs.

## Консольный клиент

```bash
go build -o bin/stt-client ./cmd/stt-client
./bin/stt-client -addr localhost:8080 -file meeting.ogg -out result.json
```

Клиент передаёт исходный файл без перекодирования, по 1 MiB, и выводит один полный
`MeetingResponse` в JSON с исходными именами protobuf-полей. Тот же JSON сохраняется
в `-out`, по умолчанию — в `<аудиофайл>.transcription.json` рядом с исходником.
Каталог назначения должен существовать. Предыдущий результат заменяется только
после успешной обработки и записи; исходный аудиофайл нельзя выбрать как `-out`.
Метрики и прогресс в stdout не добавляются; ошибки идут в stderr, код завершения — 1.
На машине клиента не нужны модели, FFmpeg и GPU. Сервер должен быть запущен отдельно.

Параметры: `-addr` (по умолчанию `localhost:8080`, без TLS), обязательный `-file`,
`-out`, `-chunk-bytes` (по умолчанию `1048576`, не больше серверного лимита) и `-timeout`
(например, `6h`, по умолчанию без deadline). Ctrl+C отменяет RPC.

## Отправка из Go

Схема для клиента, сгенерированного из обновлённого proto:

```go
func transcribeMeeting(ctx context.Context, client sttv1.GigaamClient, path string) (*sttv1.MeetingResponse, error) {
    f, err := os.Open(path)
    if err != nil { return nil, err }
    defer f.Close()
    info, err := f.Stat()
    if err != nil { return nil, err }
    stream, err := client.TranscribeMeeting(ctx, grpc.MaxCallRecvMsgSize(math.MaxInt32))
    if err != nil { return nil, err }
    if err := stream.Send(&sttv1.MeetingRequest{
        Payload: &sttv1.MeetingRequest_Header{Header: &sttv1.MeetingUploadHeader{SizeBytes: uint64(info.Size())}},
    }); err != nil { return nil, err }
    buf := make([]byte, 1<<20) // согласовать с MEETING_CHUNK_BYTES
    for {
        n, readErr := io.ReadFull(f, buf)
        if n != 0 {
            // После Send сообщение нельзя изменять; не передаём переиспользуемый buf.
            chunk := bytes.Clone(buf[:n])
            if err := stream.Send(&sttv1.MeetingRequest{
                Payload: &sttv1.MeetingRequest_Chunk{Chunk: chunk},
            }); err != nil { return nil, err }
        }
        if readErr == io.EOF || readErr == io.ErrUnexpectedEOF { break }
        if readErr != nil { return nil, readErr }
    }
    return stream.CloseAndRecv()
}
```

Вызывающая сторона должна отменить context при ошибке или завершении операции. Изменение файла во время загрузки может привести к несовпадению длины и `InvalidArgument`.

## Проверки

- `go test -race ./...`, `go vet ./...` — обработка, API, приоритет, отмена и закрытие.
- `MEETING_LARGE_UPLOAD_TEST=1 go test -v ./internal/transport -run TestMeetingUploadLargerThanProtobufMessage` — 2049 MiB через реальный gRPC с проверкой CRC и размера файла на диске; модели в этом тесте заменены тестовыми реализациями.
- `NEMOTRON_TEST_LIBRARY=/path/libnemo_speech_asr_c.so go test -v ./internal/diarization -run TestInstalledSDK` — загрузка настоящего SDK и передача его ошибок через cgo.
- Для настоящей диаризации задать `NEMOTRON_TEST_LIBRARY`, `NEMOTRON_TEST_MODEL` и `NEMOTRON_TEST_PCM` (PCM16 mono 16 kHz), запустить `go test -v ./internal/diarization -run TestRealNemotron`.

Собраны Go-приложение, SDK CPU, среда официального converter и минимальный FFmpeg. Проверены C ABI, файловое декодирование WAV, Ogg/Opus, Vorbis, MP3, FLAC, AAC/ALAC M4A и Opus/WebM. Собранный FFmpeg сохраняет тишину и обрабатывает файл длиннее лимита живого режима. Для этих проверок: `FILE_TEST_FFMPEG=/path/ffmpeg go test -v ./internal/audio -run TestFileDecoder`.

В этапе `nemotron-tools` запускается `script/test_validate_nemotron.py`: проверяет штатный F16-вес свёртки, запрет остальных F16/BF16/квантованных весов, manifest, архитектуру, число голосов и пустой GGUF. Тесты используют синтетические тензоры; это не проверка качества модели.

Сквозной inference с настоящими весами Nemotron и GigaAM, двухчасовая запись, DER/WER и GPU в этом окружении не проверены: загрузку checkpoint с Hugging Face запрещает прокси (CONNECT 403), пользовательской записи здесь нет. Сборка `nemotron-model` доходит до загрузки весов и при этой ошибке завершается, не создаёт образ без модели.
