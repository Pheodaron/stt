# Проверки

Linux amd64, Go 1.25.1, sherpa-onnx Go 1.13.8.

## Упрощённая конфигурация контейнера

- `go test ./...` и `go vet ./...` прошли в сборочном контейнере с настоящим
  статическим FFmpeg. Проверки настоящих моделей по-прежнему требуют весов
  и входных записей, указанных ниже.
- Для всех 17 параметров `FromEnv` проверены одинаковые defaults при отсутствии
  и пустой строке, а также чтение заданных значений. Отдельно проверены ошибки
  формата, диапазонов и выбора провайдера: `FromEnv` вызывает панику
  с именем неверного параметра. Проверены также несовместимые значения
  длительности, перекрытия окон, дополнения речи и тишины.
- Собранный сервер проверен с неверными `NUM_THREADS`, `MODEL_WORKERS`,
  `VAD_THRESHOLD`, `MODEL_PROVIDER` и сочетанием padding/silence:
  каждый запуск завершился с кодом 2 и сообщением `panic` до загрузки модели.
- `docker build --check` для CPU и GPU прошёл без предупреждений.
- CPU/GPU Compose разобраны с публичным `.env.example`: удалённые настройки
  точности и путей не передаются, провайдеры остаются `cpu`/`cuda`.
- Путь FFmpeg `/usr/local/bin/ffmpeg` и каталог GigaAM
  `/app/models/gigaam-v3-fp32` в константах Go совпадают с местом копирования
  файлов в обоих Dockerfile. Сервер использует только встроенную FP32-модель.

## Silero VAD и сохранение границ фраз

- WebRTC заменён на Silero v6.2.3 FP32 ONNX через sherpa-onnx. Закреплённые
  модель и MIT LICENSE скачаны с GitHub; SHA-256 проверены. Повторный
  скрипт подготовки использовал проверенный кеш. Эти проверки выполнены
  до переноса загрузки VAD в build-stage `vad-model`.
- `go test -race ./...` с настоящим Silero и `go vet ./...` прошли.
  Регрессии покрывают предысторию речи, неполные окна, EOF/lookahead,
  отсутствие искусственных нулей в ASR, финализацию на тишине, изоляцию VAD,
  освобождение native-ресурсов и сохранение аудио при лимите длительности.
- На проверочной русской записи Silero сохранил все 180 640 исходных сэмплов.
  Фильтрация целой записи и чанков по 71, 319, 1600 и 15999 сэмплов дала
  побайтно одинаковый PCM. Добавление секунды тишины перед записью и после неё
  не обрезало исходную речь.
- Полный FFmpeg → Silero FP32 → GigaAM конвейер проверен на доступных INT8-весах
  GigaAM: запись целиком и WAV-чанки по 1,307 секунды дали одинаковый финальный
  текст с первыми «Ничьих» и последними «дуб зелёный». Это регрессия конвейера,
  не оценка качества FP32 GigaAM или пользовательского аудио ВКС.
- CPU-образ собран и проверен без сети, с read-only весами и UID 65532:
  gRPC и WebSocket, buffered/unbuffered, получение первых и последних слов,
  завершение через SIGTERM с кодом 0.
- Silero также проверен с нативными GPU-библиотеками sherpa/ORT при
  `Provider=cpu`: такая конфигурация используется для VAD в CUDA-контейнере.
  Dockerfile.gpu прошёл `docker build --check`; настоящая CUDA не проверена.
- Mise dispatch CPU/CUDA, объединение Compose и восемь Mermaid-схем проверены.

Для настоящего optional-теста фильтрации задайте `VAD_TEST_MODEL` и
`VAD_TEST_AUDIO`, затем выполните `go test ./internal/audio -run TestRealSilero`.
Для полного конвейера задайте также `MODEL_TEST_AUDIO` и `MODEL_PROVIDER`;
FP32-веса должны находиться в `/app/models/gigaam-v3-fp32`,
а FFmpeg — в `/usr/local/bin/ffmpeg`. Выполните
`go test -v ./internal/stt -run TestRealChunkedPipeline`.
`MODEL_TEST_EXPECT` задаёт ожидаемые фрагменты текста через запятую.
Эти тесты ничего не скачивают. Тестовые утилиты не добавляют локальный режим
запуска сервера и не входят в runtime-образы.

ВКС-записи пользователя и эталонные расшифровки в окружении отсутствуют;
WER/CER и оптимальные VAD-пороги для них не измерялись.

## Остальные проверки и ограничения окружения

- Go-тесты, включая race detector и настоящий INT8-инференс, прошли.
  INT8-веса использовались только как доступный тестовый набор; скачивание
  такой модели из проекта удалено. FP32 остаётся настройкой по умолчанию.
- `go vet` прошёл; сервер собирается с CGO.
- Проверены gRPC wire-имена, streaming/unary, финализация, JSON-RPC,
  notifications, batch, ошибки и изоляция сессий.
- Проверены FFmpeg/Silero, границы окон, лимиты, отмена,
  скользящее окно и сброс состояния после ошибки.
- CPU-образ после упрощения собран через Docker и проверен под UID 65532,
  без сети, с read-only моделью. gRPC и WebSocket распознают запись
  с буферизацией и без неё. SIGTERM завершает сервер с кодом 0.
- CUDA runtime-архив скачан, SHA-256 проверен. Совместимость Go C API
  проверена распознаванием в CPU-режиме с GPU-библиотеками.
- CUDA-проверка отклоняет отсутствие execution provider или драйвера,
  без подмены режима и без сообщения о готовности.

Образы собираются задачами `build:cpu` и `build:gpu`, protobuf генерирует `proto`.
Для полного сценария используются `build:cpu`/`build:gpu`, `run:cpu`/`run:gpu`,
`logs`, `stop`. Задачи запуска автоматически вызывают `init` для `.env`. Клиент, бенчмарк, локальный запуск
Go-сервера не возвращались. Запуск описан в `compose.yaml`, CUDA —
в дополнении `compose.gpu.yaml`; mise вызывает Podman Compose.
Go и компилятор для сборки серверных образов устанавливаются внутри build-stage.
`mise run proto` проверен без глобально установленных Go-плагинов: пути получены
через `go tool -n` по директивам `tool` в `go.mod`, с версиями 1.36.9 и 1.5.1.
Сгенерированные файлы совпали с исходными. Команда `go install tool` также прошла.
Go 1.25.1 закреплён только у задачи генерации, не у сборочных задач Podman.
Проверка Dockerfile.gpu через `docker build --check` прошла без предупреждений.

Гайд и команды mise проверены отдельно:

- `init` создаёт конфигурацию и не перезаписывает существующие настройки.
- Каталог модели на хосте и предварительная проверка его файлов больше не нужны: веса копируются в образ при сборке.
- Конфигурации CPU и CUDA разобраны настоящим `podman-compose` 1.6.0
  в режиме `config --dry-run`: проверены объединение YAML, FP32, provider,
  образ, порт, UUID CDI и SELinux. В dry-run запуска с подставным Podman
  проверено преобразование CUDA `devices` в `--device nvidia.com/gpu=...`.
- Mise вызывает Compose up, logs и down. `down` по базовой конфигурации
  адресует тот же проект `vks-stt` и для CUDA. Это проверка команд,
  не настоящего запуска Podman/CDI или распознавания на FP32.
- Экспорт выполняется автоматически в этапах `model-tools`/`model-export`
  обоих Dockerfile. Ручная подготовка весов и внешний volume удалены.
  Python/PyTorch остаются в build-stage, checkpoint — в кеше сборщика.
- Этап `model-tools` с Python 3.11.13, CPU PyTorch/torchaudio 2.8.0
  и закреплённым GigaAM собирается отдельно для проверок экспортера.
- Готовая модель копируется отдельным слоем перед приложением.
  В обоих образах и в коде используется путь `/app/models/gigaam-v3-fp32`.
- Регрессионные тесты `tests/test_model_export.py` выполнены внутри образа
  под UID 1000, без сети и исходных весов. Используется настоящий `RNNTJoint`
  из закреплённого GigaAM со случайными весами и вызов joiner из закреплённого
  upstream exporter. Исходный вызов воспроизводит `Got: 1 Expected: 8`.
  Исправленный вызов экспортирует `enc=[1,768,1]`, `dec=[1,320,1]`;
  результат ONNX Runtime совпадает с PyTorch (`rtol=1e-5`, `atol=1e-6`).
  Валидатор отклоняет прежний батч 8 до записи `precision.json`.
  Также проверено отклонение изменённого upstream. Все три теста прошли.

Повторить регрессионные тесты можно без загрузки checkpoint:

```bash
podman build -f Dockerfile.cpu --target model-tools -t localhost/vks-stt-go:model-tools .
podman run --rm --network=none --userns=keep-id \
  --volume "$PWD:/src:ro,z" --entrypoint python3 \
  localhost/vks-stt-go:model-tools /src/tests/test_model_export.py -v
```

Проверка новой сборки с моделью внутри образа:

- После объединения с переходом на Silero повторно прошли `go test ./...`
  со статическим FFmpeg и три теста экспортера. Этап `vad-model` скачал
  настоящую Silero v6.2.3 и MIT LICENSE; обе SHA-256 совпали.

- `docker build --check` для CPU и GPU прошёл без предупреждений.
- Реальные Compose-конфигурации CPU/GPU разобраны через `docker compose config`:
  внешних volumes модели нет, путь модели совпадает со встроенными файлами,
  `MODEL_WORKERS=1` и `NUM_THREADS=2` сохранены.
- `model-tools` собран из нового Dockerfile; все три теста экспортера повторно прошли
  под UID 1000 без сети.
- До объединения с переходом на Silero для проверки упаковки создан отдельный временный образ с синтетическими ONNX-графами
  и неизменённым runtime-разделом `Dockerfile.cpu`. Два контейнера из этого образа
  дошли до `ready` под UID 65532 без сети и mounts. Файлы модели доступны для чтения,
  Python, checkpoint и инструменты экспорта отсутствуют. Оба контейнера имеют один
  image ID. Это проверка упаковки и запуска, а не распознавания настоящей GigaAM.
- Код обработки, пул recognizer и значения настроек параллельности не менялись.

Podman и NVIDIA GPU в окружении отсутствуют. Полный запуск Podman/CDI
не проверен. Загрузка базового NVIDIA-образа ранее завершилась нехваткой
места при диске 32 ГБ и Docker vfs; CUDA-инференс не выполнен.
Новая сборка `--target model-export` доходит до загрузки checkpoint GigaAM,
после чего прокси среды возвращает HTTP 403 для
`cdn.chatwm.opensmodel.sberdevices.ru`. Полная сборка образа с оригинальными
FP32-весами и распознавание на них пока не проверены; ошибка не маскируется
и не создаёт runtime без модели.

Предыдущие CPU-замеры INT8: [cpu-inference.md](cpu-inference.md).
Они не являются оценкой скорости или качества FP32/CUDA.

## Компактный FFmpeg

FFmpeg 8.1.3 собирается из commit `1041abdc962f4cc4f394aa8de9dc5236c0c3b9e7`
со статической musl, без GPL/nonfree и внешних библиотек кодеков. Общий скрипт
`script/build-ffmpeg.sh` используется CPU- и GPU-Dockerfile. Бинарник и лицензии
копируются из отдельного этапа; сборочные инструменты остаются в build-stage.

Измерение Linux amd64 через Docker, размеры без сжатия:

| Набор | Размер |
|---|---:|
| Статический бинарник FFmpeg | 11 238 152 байта (11,2 МБ) |
| Debian bookworm-slim + ca-certificates + libstdc++6 + пакет ffmpeg | 539,3 МБ |
| Та же основа + статический FFmpeg и лицензии | 94,7 МБ |

Экономия runtime-набора — 444,6 МБ. В сравнение не включены Go-сервер,
sherpa/ONNX Runtime, CUDA и модель. Пакетная установка добавляла 202 пакета;
компактный вариант копирует FFmpeg без его динамических библиотек.

Проверено:

- Архив исходников проходит SHA-256; `readelf` не находит динамический загрузчик.
- Бинарник запускается под UID 65532 в `scratch` без сети и системных библиотек.
- `go test -v ./internal/audio` прошёл со статическим FFmpeg: WAV, Ogg/Opus,
  Ogg/Vorbis, MP3, FLAC, AAC/MP4, ALAC/MP4 и Opus/WebM через stdin;
  проверены mono PCM16/16 кГц, длительность и наличие сигнала.
- Сохранены проверки точного PCM из WAV, неверного аудио, ограничения входного
  размера и длительности декодирования и отмены контекста. Проверка WebRTC VAD
  относилась к версии до перехода на Silero.
- Shell-синтаксис сборочного скрипта и генератора фикстур, форматирование Go
  и `docker build --check` для GPU-Dockerfile прошли.
- До включения весов был собран CPU-образ размером 145,4 МБ без модели. Внутри него под UID 65532
  проверены путь `/usr/local/bin/ffmpeg`, доступность лицензий, отсутствие
  `/usr/bin/ffmpeg` и декодирование Ogg/Opus в 8000 байт PCM16 mono/16 кГц.
  Для sherpa-модуля использован существующий build-arg `GONOPROXY`, поскольку
  зеркало Go перенаправляет его архив на недоступный в окружении хост.

Фикстуры содержат только синтетический тон и воспроизводятся скриптом
`script/generate-audio-fixtures.sh` в контейнере с полным FFmpeg.
ARM64 и CUDA-инференс в этой проверке не запускались.
