# Проверки переноса

Проверено в Linux amd64 15 октября 2026; Go 1.25.1, sherpa-onnx Go 1.13.8.

**После изменения приоритета на качество:** FP32 стал режимом по умолчанию.
Проверены Go-тесты выбора точности и подготовка закреплённого экспортера без
квантования (`EXPORT_PREPARE_ONLY=1 sh script/export-model-fp32.sh`).
Исходные веса недоступны из окружения из-за сетевого запрета (HTTP 403), поэтому
FP32-экспорт и инференс пока не проверены. Ниже результаты реального распознавания
и CPU-контейнера получены с INT8-весами; они не подтверждают качество FP32.

**После добавления CPU/CUDA и рефакторинга читаемости:** сервер, клиент,
JSON-RPC, WebSocket-соединения, FFmpeg и VAD разделены по файлам и небольшим
функциям. Повторно выполнены race-тесты, vet, сборка и подготовка FP32-экспортера.

- `go test -race ./...` — прошёл, включая дополнительный тест настоящей GigaAM
  с `MODEL_TEST_AUDIO` и проверкой ожидаемого слова «лукоморья».
- `go vet ./...` — прошёл.
- `make build` — прошёл, в том числе повторная сборка поверх существующей bin/.
- gRPC: проверены исходные wire-имена, унарное распознавание и streaming с настоящей
  моделью, optional-поля, ошибка неверного аудио, финализация при CloseSend.
- WebSocket: проверены настоящий клиент и модель в обоих режимах, JSON-RPC ошибки,
  batch, notifications, позиционные параметры, изоляция буферов подключений.
- Аудио: WAV → чистый PCM, неверный контейнер, лимиты входа и декодированной
  длительности, отмена FFmpeg, тишина, нормализация int16.
- Буфер: смена окон, размер 1, длительности фреймов 10/20/30 мс,
  ограничение окна, сброс после ошибки, сохранение последнего partial.
- Dockerfile.cpu: образ собран; распознавание выполнено под UID 65532 с
  `--network none`, моделью в read-only томе и клиентом внутри контейнера.
  Проверены gRPC и WebSocket, каждый с буферизацией и без неё. Корневая файловая
  система контейнера read-only; `/tmp` размещён в tmpfs.
  SIGTERM завершил сервер с кодом 0.
- CPU/CUDA Compose-конфигурации проверены через `docker compose config`,
  включая выбор provider, FP32 для CUDA и reservation устройства NVIDIA.
- CUDA runtime-архив sherpa 1.13.8 скачан, SHA-256 проверен; скрипт установки
  успешно заменил комплект библиотек в отдельном тестовом каталоге.
  Go-бинарник с GPU-библиотеками выполнил настоящее распознавание в режиме CPU.
  Это проверка совместимости C API, а не CUDA-вычислений.
- При выборе CUDA со штатными CPU-библиотеками проверка отклоняет отсутствие
  CUDAExecutionProvider; с GPU-библиотеками без драйвера сервер завершается с
  ошибкой `NVIDIA driver is unavailable`, не сообщает готовность и не запускает CPU.
- Полная сборка Dockerfile.gpu не проверена: загрузка базового NVIDIA-образа
  завершилась `failed to register layer: no space left on device` в окружении
  с диском 32 ГБ и драйвером Docker vfs. Настройки Docker не изменялись.
  `docker build --check -f Dockerfile.gpu .` прошёл без предупреждений.

В Docker используется штатный C++/ONNX Runtime из Go-пакета sherpa; Python
в runtime-образ не устанавливается. NVIDIA GPU и драйвер в окружении отсутствуют:
CUDA-распознавание, FP32, ARM64, точность на пользовательском корпусе и нагрузка
с большим числом клиентов не проверялись.

Численные CPU-замеры и их ограничения — [cpu-inference.md](cpu-inference.md).
