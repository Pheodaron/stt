# Проверки

Linux amd64, Go 1.25.1, sherpa-onnx Go 1.13.8.

- Go-тесты, включая race detector и настоящий INT8-инференс, прошли.
  INT8-веса использовались только как доступный тестовый набор; скачивание
  такой модели из проекта удалено. FP32 остаётся настройкой по умолчанию.
- `go vet` прошёл; сервер собирается с CGO.
- Проверены gRPC wire-имена, streaming/unary, финализация, JSON-RPC,
  notifications, batch, ошибки и изоляция сессий.
- Проверены FFmpeg/VAD, длительности фреймов, лимиты, отмена,
  скользящее окно и сброс состояния после ошибки.
- CPU-образ после упрощения собран через Docker и проверен под UID 65532,
  без сети, с read-only моделью. gRPC и WebSocket распознают запись
  с буферизацией и без неё. SIGTERM завершает сервер с кодом 0.
- CUDA runtime-архив скачан, SHA-256 проверен. Совместимость Go C API
  проверена распознаванием в CPU-режиме с GPU-библиотеками.
- CUDA-проверка отклоняет отсутствие execution provider или драйвера,
  без подмены режима и без сообщения о готовности.

Образы собираются задачами `build:cpu` и `build:gpu`, protobuf генерирует `proto`.
Для полного сценария добавлены `init`, `model:prepare`, `model:check`,
`run:cpu`, `run:gpu`, `logs`, `stop`. Клиент, бенчмарк, локальный запуск
Go-сервера не возвращались. Запуск описан в `compose.yaml`, CUDA —
в дополнении `compose.gpu.yaml`; mise вызывает Podman Compose.
Go и компилятор для сборки серверных образов устанавливаются внутри build-stage.
`mise run proto` проверен без глобально установленных Go-плагинов: пути получены
через `go tool -n` по директивам `tool` в `go.mod`, с версиями 1.36.9 и 1.5.1.
Сгенерированные файлы совпали с исходными. Команда `go install tool` также прошла.
Go 1.25.1 закреплён только у задачи генерации, не у сборочных задач Podman.
Проверка Dockerfile.gpu через `docker build --check` прошла без предупреждений.

Гайд и команды mise проверены отдельно:

- `init` создаёт конфигурацию и не перезаписывает существующие настройки.
- При отсутствии модели задача запуска останавливается до вызова Compose.
- Конфигурации CPU и CUDA разобраны настоящим `podman-compose` 1.6.0
  в режиме `config --dry-run`: проверены объединение YAML, FP32, provider,
  образ, порт, UUID CDI и SELinux. В dry-run запуска с подставным Podman
  проверено преобразование CUDA `devices` в `--device nvidia.com/gpu=...`.
- Mise вызывает Compose up, logs и down. `down` по базовой конфигурации
  адресует тот же проект `vks-stt` и для CUDA. Это проверка команд,
  не настоящего запуска Podman/CDI или распознавания на FP32.
- Подготовка закреплённого экспортера прошла через `model:prepare` с
  `EXPORT_PREPARE_ONLY=1` и `MISE_DISABLE_TOOLS=python`, используя уже
  установленный Python 3.12.14. Скачивания/экспорта весов в этом режиме нет.
  Установка закреплённого Python 3.11.13 через mise в окружении блокируется
  доступом к `mise-versions.jdx.dev`, поэтому она здесь не проверена.
- Повторная подготовка пропускает полный набор шести файлов; отсутствие
  `precision.json` или лицензии не считается завершённым экспортом.

Podman и NVIDIA GPU в окружении отсутствуют. Полный запуск Podman/CDI
не проверен. Загрузка базового NVIDIA-образа ранее завершилась нехваткой
места при диске 32 ГБ и Docker vfs; CUDA-инференс не выполнен.
Хост исходных весов GigaAM заблокирован сетевой политикой (HTTP 403), поэтому
FP32-экспорт и распознавание на FP32 пока не проверены.

Предыдущие CPU-замеры INT8: [cpu-inference.md](cpu-inference.md).
Они не являются оценкой скорости или качества FP32/CUDA.
